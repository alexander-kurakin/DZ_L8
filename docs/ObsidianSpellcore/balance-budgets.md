# Balance budgets — сила игрока vs сила волны

**Статус:** черновик iter.3 — целевые **Slack**, расчёт на текущих цифрах из [[balance]]  
**Не дублирует:** канонные статы и composition — только в [[balance]]  
**Связь:** overlap / spawn interval **не** являются главным рычагом, если `Damage_total ≫ Threat_HP`

---

## 1. Определения

| Термин | Формула / смысл |
| ------ | ---------------- |
| **Threat_HP** | Σ `Max HP` всех врагов волны (без учёта пути) |
| **Threat_tower** | Урон башне от **дошедших** кошек: `leaked_cats × 500` (отдельная метрика, не входит в Slack) |
| **Damage_field** | Урон от растений на поле за волну (мины, toxic, турели) с учётом геометрии |
| **Damage_passive** | Брат + LMB + прочее вне Essence (за волну) |
| **Damage_total** | `Damage_field + Damage_passive` |
| **Slack** | `Damage_total / Threat_HP` |
| **Essence_cum** | Накопленная Essence к **началу подготовки** этой волны (100% сбор дропа) |
| **Slots** | `paths × 3` пояса (O/M/I) |

**Целевой Slack (утверждено):**

| W1 | W2 | W3 | W4 | W5 |
| -- | -- | -- | -- | -- |
| **1.5** | **1.25** | **1.1** | **1.0** | **0.8** |

`Slack < 1` на W5 = волна **сильнее** бумажного HP-бюджета игрока → нужна хорошая расстановка, реакция, bailout или потеря HP башни.

## 5. Модель урона за волну

### 5.1 Пассив (упрощённо)

Длительность боя `T_wave` (спавн + подход с `EnemySpawnRadius` 90) — **допущение для таблицы**:

| Wave | T_wave (сек) | Brother max* | LMB на кошек** |
| ---- | ------------ | ------------ | -------------- |
| 1 | 40 | 1330 | 450 (3×150, 1 каст) |
| 2 | 45 | 1500 | 450 |
| 3 | 50 | 1660 | 450 |
| 4 | 55 | 1830 | 750 (5×150) |
| 5 | 60 | 2000 | 900 (6×150) |

\* `floor(T / 3) × 100`, если все цели на M/I (верхняя граница).  
\** При грамотном использовании LMB по кошкам; танки/драконы = 0.

### 5.2 Поле (мины)

```
Damage_field_mines ≈ N_mines × 190 × K_mine
```

**K_mine** — доля врагов, получивших ровно один proc на своём пути (геометрия):

| Ситуация | K_mine (ориентир) |
| -------- | ----------------- |
| 1 путь, мины O+M, враги по одному | ~1.0 |
| 2 пути, 5 мин на 6 слотов | ~0.9–1.0 |
| 6 путей, мины только на части spokes | ~0.5–0.7 |
| Inner-мина при угрозе с Outer | **0** на этот spoke |

### 5.3 Сводная формула

```
Damage_total = N_mines × 200 × K_mine + Damage_toxic + Damage_turret + Damage_brother + Damage_LMB

Slack = Damage_total / Threat_HP
```

Toxic / turret в ранних волнах часто **0** (не открыты или нет бюджета). W4+ — отдельная строка в playtest.

## 8. Рычаги (приоритет по влиянию на Slack)

Чтобы попасть в целевой Slack, крутить в первую очередь:

| # | Рычаг | Влияние | Направление для iter.3 |
| - | ----- | ------- | ---------------------- |
| 1 | **Mine cost** / **drops** | Прямо `N_mines` и Essence_cum | ↑ cost или ↓ drop → меньше `Damage_field` |
| 2 | **Mine damage** / **enemy HP** | Hits-to-kill | ↑ HP или ↓ mine 200 → выше Threat / ниже field |
| 3 | **Paths unlock** `[1,2,4,6,6]` | Потолок слотов | Задержать 6 paths до W5 → меньше K×N на W4 |
| 4 | **Brother** dmg / interval | `Damage_passive` на всех волнах | Снижение сильнее всего на W2–W3 |
| 5 | **Free mines** (2→1) | Только W2 spike | −200 field на W2 |
| 6 | **LMB** | Только кошки | Меньше влияет с W4 (много танков) |
| 7 | Spawn overlap | Тайминг | **Не закрывает** разрыв Slack |

### Обратный расчёт (W4 → Slack 1.0)

Нужно: `Damage_total ≈ 3400`, сейчас ~5200 → убрать **~1800** урона за волну.

Примеры **одиночных** круток (иллюстрация, не рекомендация пакета):

| Изменение | Δ Damage_field / passive (оценка) |
| --------- | --------------------------------- |
| Mine 200→**150** | −18×50×0.55 ≈ **−495** на полной доске |
| Brother 100/3с → **70/3с** | −~550 за волну |
| Cat drop 25→**18** (+ цепочка cum) | Меньше мин к W4: **−800+** field |
| Paths W4: **4** вместо 6 | −4×200×0.55 ≈ **−440** mines |

Обычно нужен **пакет 2–3 рычага**, не один.

## 9. Workflow

1. Задать **Slack** по волнам (секция 1) — **done**.  
2. Зафиксировать **Threat_HP** (секция 3).  
3. Посчитать **Target Damage_total** = Threat × Slack.  
4. Оценить каналы (секция 6) на текущих `.asset`.  
5. Подкрутить рычаги (секция 8) → перенести цифры в [[balance]] → `.asset`.  
6. Playtest: проверить **Threat_tower** (leak кошек) отдельно — Slack по HP не гарантирует урон башне.

## 13. Композиция волн (spawn groups)

**Правило кода** (`WaveSpawnPlanService`): **одна `SpawnGroup` = один путь**.  
`EnemiesCount > 1` внутри группы = **поезд на одной линии** (все с одного spoke).

| Ошибка | Симптом |
| ------ | ------- |
| 2 танка в одной группе | Оба на одном пути; 2 мины (O+M) бьют **по разу каждый** танк → 380 dmg; при HP 500+ брат не успевает, башня горит |
| Только цифры HP/урона без split групп | Slack на бумаге ок, teach W2 ломается |

### Целевая структура (iter.3.1)

| Волна | Группы | Замысел |
| ----- | ------ | ------- |
| W1 | 1× cats | LMB |
| W2 | cats → **1 tank** → **1 tank** (пауза **3с**) | 2 пути, O+M на каждый; второй танк после добивания первого |
| W3 | cats → **1 tank** → **1 tank** → dragon | Турель/inner mine vs дракон; танки не в купе |
| W4–W5 | mixed groups (уже в `Intro4`/`Intro5`) | overlap по **разным** путям в одной группе — ок |

При добавлении врагов: **новый путь = новая группа**, не `EnemiesCount++`.
